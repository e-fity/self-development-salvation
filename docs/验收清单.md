# 人工验收清单（M2 灰盒）

> 对应 PRD v0.2 §9「验收标准」的 10 条。第一条自动化脚本能覆盖一部分（见 §0.1），手感、听感、观感仍需人看。
> 前置：`godot --path game`（或导出包），分辨率 1600×900 窗口，音量 50%。

## 0.1 自动验收（可重复，约 40 秒）

在仓库根目录跑：

```powershell
$env:GODOT_BIN = "C:\path\to\Godot_v4.7.2-stable_win64_console.exe"
$env:SALVATION_SHOT_DIR = "$PWD\_backup\shots"
$env:SALVATION_SAVE_DIR = "$PWD\_backup\test-save"
& $env:GODOT_BIN --path game res://tests/auto_accept.tscn --resolution 1280x720
echo $LASTEXITCODE   # 0 = 24 项自动断言全过
```

脚本会真实开窗、注入按键，检查并截图：

- 标题页、关卡开局、命中、逆鳞、零点、Boss 战、结算共 7 张 PNG（存在 `SALVATION_SHOT_DIR`）；
- 按键到起手 ≤2 物理帧、三连伤害 ≥30、闪避无敌与位移 ≥120px、逆鳞进 CD、零点无敌并清能量、Boss 激活、结算暂停、结算时隐藏 HUD/教学；
- Boss 战 4 秒帧率采样（1280×720 实测平均 59–64fps、1% low ≥58，视 VSync 与机器而定）。

**它不能替代人**：听不到音效是否分档、看不出动画是否顺滑、测不到鼠标/键盘的真实延迟，也无法判断「打起来爽不爽」。这些仍走下面的 10 条。

## 0. 调试速查

| 键 / 命令 | 作用 |
| --- | --- |
| F1 | 显示 / 隐藏调试面板 |
| F2 | 无敌开关（面板状态行显示「无敌 开」） |
| F3 | 秒杀离玩家最近的敌人 / Boss |
| F4 | 传送到 Boss 面前 420px |
| F5 | 冻结所有敌人 AI（解冻后 Boss 至少等 0.5s 再出手） |
| F6 | 显示引擎碰撞形状 |
| `（反引号） | 打开控制台，Enter 执行，Esc 关闭 |
| `god` / `freeze` / `kill` / `warp <x>` / `boss` / `help` | 控制台命令 |

建议每验一条前先执行 `god` 或 `freeze`，避免中途死亡打断观察；验完 `god` 再关掉。

> 调试面板默认收起（F1 打开），右上角连击数与 Boss 血条不会被挡。

## 1. 启动到结算 ≤ 8 分钟

1. 从标题页按 Enter（或点「开始游戏」）进关；
2. 正常清完 4 只木桩 + Boss，不跳关；
3. 记录 `开始 → 结算页出现` 的秒表时间。

预期：≤ 480s，且全程无卡顿、无脚本报错（控制台窗口无 `SCRIPT ERROR`）。
备注：想快速到 Boss 可用 F4 / `boss`，但这会低估真实时长，需另跑一遍全流程。

## 2. 按键到起手 ≤ 100ms

1. 站在空地上，连按 J / 鼠标左键 10 次；
2. 观察角色是否在按下瞬间进入挥砍（无输入吞掉）；
3. 用调试面板看状态行是否立即变为「攻击」。

预期：10 次全部即时响应，没有「按了不出招」。
备注：窗口模式下输入延迟受显示器/垂直同步影响，测试机需关闭 VSync 或记录为环境因素。

## 3. 地面三连成功率 ≥ 9/10

1. 对木桩连续按 3 次攻击（节奏约 0.2s 一次）；
2. 看到第三段重击（击退 160、伤害数字更大）算成功；
3. 做 10 轮，记录成功次数。

预期：≥ 9 次。若频繁断连，先确认没有在硬直结束前 0.15s 之外乱按（缓冲窗口只认最后 0.15s）。

## 4. 闪避成功率 ≥ 18/20

1. 让木桩进入攻击前摇（变红）；
2. 在红光亮起后按 Shift / U 闪避，穿过攻击；
3. 做 20 次，记录角色是否掉血。

预期：≥ 18 次不掉血（前 3 帧无敌）。掉血多半是按早了。

## 5. Boss 三阶段

1. 用 F4 / `boss` 到 Boss 前，打到 66% 血；
2. 观察 Boss 变红、1 秒无敌、之后攻速变快（阶段 2）；
3. 打到 33% 血，确认进入阶段 3（间隔更短、跳劈/召唤更频繁）。

预期：两次转阶段都有变色 + `boss_phase` 音效 + 短暂无敌，且无敌期间打不掉血。
备注：阶段 2 起召唤 2 只木桩，确认它们不计金币、不算评价。

## 6. 命中反馈四件套

对木桩打一套三连，逐项确认：

| 反馈 | 预期 |
| --- | --- |
| 命中停顿 | 每次命中画面短暂冻结（约 40–80ms），三段最明显 |
| 震屏 | 轻/中/重三档幅度递增（2/4/6px） |
| 伤害数字 | 橙黄色数字上飘 0.45s，暴击/重击字号更大 |
| 音效 | `swing_light` / `swing_heavy` / `hit_light` / `hit_mid` / `hit_heavy` 分档播放 |

另：F1 面板把「命中停顿」调到 0，确认不再停顿；调到 3，确认明显变慢——验证滑条生效。

## 7. 死亡后 3 秒内可重试

1. 关掉无敌，站着让 Boss 打死；
2. 记录从倒地到能重新操作的时间。

预期：≤ 3s（当前 `respawn_delay = 1.5s` + 1s 无敌），回到最近检查点，血与能量重置。

## 8. 结算评价

分别制造三种局，确认评级与分项：

| 局 | 操作 | 预期 |
| --- | --- | --- |
| S | 全程不受伤、连击 ≥30、用时 ≤150s | S，分项 40 + 35 + 25 |
| A | 受伤 1–3 次、连击 15–29、用时 ≤240s | A |
| B | 受伤 ≥4 次或时间长 | B |

另确认结算页「评分 x · 时间 a / 受伤 b / 连击 c」分项与实际表现一致，「再来一次」能立刻重开。

## 9. 强杀不丢档

1. 通关一次，记下金币 / 通关次数；
2. 在**写档瞬间**（结算页出现后 1 秒内）用任务管理器结束进程，重复 5 次；
3. 每次重启看标题页摘要。

预期：5 次都存在 `save.json` 或 `save.bak` 中至少一份可读，金币/次数不回退到 0（最多丢最后一次结算）。
备注：这是模拟断电的最低成本办法；真实掉电语义仍缺 `fsync`。

## 10. 压力场景 60s 平均 ≥ 58fps

1. 阶段 3 召唤 2 只木桩 + 玩家连续三连 + 特效全开；
2. 用 F1 面板或外部工具记录 60s 平均帧率；
3. 同一场景关掉伤害数字再测一次作对照。

预期：平均 ≥ 58fps，1% low ≥ 45fps；若掉帧，记录是否集中在多目标 `intersect_shape` 或伤害数字创建。

## 已知环境限制

- headless（`--headless`）下没有渲染与音频设备，本清单无法自动完成；冒烟测试只覆盖逻辑不变量。
- 沙箱环境写 `%APPDATA%` 会失败，`user://logs` 打不开属环境问题，不是工程缺陷。
- 音效 L / I 目前复用 `hit_heavy`，听到同一声音不算失败。
