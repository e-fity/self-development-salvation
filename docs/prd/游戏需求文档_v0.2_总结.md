## 三、游戏设计核心

### 3.1 核心循环

```
进关 → 清小怪 → 捡掉落 → 打 Boss → 结算 → 升级 / 换装备 → 下一关
```

死亡后 3 秒内可原地复活一次（消耗金币，限 1 次），否则从最近检查点重来。Boss 战死亡从 Boss 入口重来，不重打前四波。

### 3.2 单局节奏（5 分钟基准）

|段落|内容|时长|累计|教学点|
|-|-|-|-|-|
|开场|镜头推进、独白、雨声|0:20|0:20|—|
|第一波|3 近战|0:45|1:05|普攻与三连|
|推进|平台跳跃、破坏空调外机|0:30|1:35|跳跃与闪避|
|第二波|2 近战 + 1 远程|1:00|2:35|闪避躲弹道|
|推进|检查点、广告牌|0:20|2:55|技能 1|
|第三波|1 盾兵 + 2 近战|1:10|4:05|绕后破防|
|第四波|2 近战 + 1 远程 + 1 盾兵|1:00|5:05|综合考验|
|Boss|三阶段 + 演出|2:00|7:05|预留死亡重试|
|结算|评价、金币、经验|0:30|7:35|含「再来一次」|

这张表是排期与验收的共同基准：实际进度与它差 20% 以上，就要回头查是内容多了还是节奏慢了。

### 3.3 叙事（v0.2 新增）

**故事内核**：一个蓝发橙眼的女孩，在城市最亮的天台，替一个说不出口的人，打完最后一场架。

|幕|时间点|画面|文字量|
|-|-|-|-|
|第一幕：雨|开场 20 秒|天台边缘，雨幕，霓虹倒影|独白 3 行|
|第二幕：夜巡|Boss 战前|镜头拉远，城市在脚下亮着|独白 1 行|
|第三幕：黎明|结算页|雨停，天边泛白|收尾 2 行|

> 开场：「他们说，站在全城最高的地方，就能把话喊出去。」「可我不需要喊。」「我只需要打完这一场。」
> Boss 前：「夜巡……原来你一直在这里等我。」
> 结算：「雨停了。」「明天，还要继续开发自己。」

全文正文控制在 10 行以内，避免变成视觉小说。文案集中到 `strings.csv`，不写死在场景里。

|动作|键盘|手柄（Xbox）|说明|
|-|-|-|-|
|左右移动|A / D|左摇杆 / 十字键|2D 横版，无上下移动|
|跳跃|空格（W）|A|可二段跳（第二段 0.8 倍高）|
|普攻（三连）|鼠标左键（J）|X|连按接续，第三段击飞|
|技能 1「橙闪」|K|Y|6 秒冷却|
|技能 2「逆鳞」|L|B|10 秒冷却|
|闪避|Shift（U）|RB|1.2 秒冷却，1–3 帧无敌|
|大招「零点」|I|RT|能量满可用|
|互动 / 拾取|E|X（无敌人时）|自动拾取为主|
|暂停|Esc|Start|冻结游戏逻辑|

### 4.2 手感五通道

|通道|参数|取值|
|-|-|-|
|命中停顿|冻结时长|轻 40ms / 中 55ms / 重 80ms（按伤害 <10 / 10–20 / >20 分档）|
|命中停顿|修正|暴击 +20ms（上限 120ms）；Boss 受击 ×1.2|
|震屏|幅度|轻 2px / 中 4px / 重 6px；Boss 技能 +2px|
|受击反馈|闪白|0.08s 全身白叠加|
|受击反馈|击退|玩家招式 40–120px；受击方 60px|
|连击计数|窗口|3.0 秒内再命中续接，断连清零|
|伤害数字|样式|普通白 12pt；暴击黄 16pt 上浮 0.4s，可关闭|

分档函数：`hitstop\\\_ms = 40 if dmg < 10 else (55 if dmg <= 20 else 80)`

### 4.3 攻击帧数据（15fps，每帧 66.7ms）

|动作|总帧|起手|判定|收招|可取消|倍率|备注|
|-|-|-|-|-|-|-|-|
|普攻 1|6|1–2|3|4–6|第 4 帧接普攻 2|1.00|—|
|普攻 2|6|1–2|3|4–6|第 4 帧接普攻 3|1.00|—|
|普攻 3|8|1–3|4–5|6–8|第 6 帧接闪避|1.50|命中击飞，击退 80px|
|跳攻|7|1–2|3–4|5–7|第 5 帧接二段跳|1.00|空中唯一主动攻击|
|橙闪|8|1–2|3–5|6–8|第 6 帧接普攻|1.50|位移 220px，3–5 帧无敌|
|逆鳞|10|1–3|4|5–10|第 8 帧接闪避|1.20|半径 120px，2s 霸体|
|零点|24|1–6|7–12|13–24|不可取消|4.00|全屏，7–12 帧无敌|
|闪避|5|1|1–3（无敌）|4–5|—|0|位移 160px，可穿身|
|受击|4|1（硬直）|—|2–4|—|0|0.25s 硬直，接 0.5s 无敌|

三条硬规则：

1. 起手帧不可取消（防无脑轻击）；收招前 N 帧可被下一段或闪避取消（保流畅）。
2. 判定帧只结算一次命中，同一目标单次攻击内不重复受伤。
3. 判定帧之前被打断，不产生伤害，也不消耗冷却。

三连总时长 = (6+6+8−2×2)/15 ≈ **1.07 秒**，落在动作游戏 0.9–1.2 秒的合理区间。

### 4.4 伤害公式

```
最终伤害 = max(1, (攻击力 × 技能倍率 − 防御) × 暴击倍率 × 连击加成 × 评价 / 霸体修正)
```

|项|取值|说明|
|-|-|-|
|攻击力|ATK（初始 12）|受装备与等级影响|
|技能倍率|见 4.3 / 6.3|普攻 1.0、三连末段 1.5、大招 4.0|
|防御|DEF（初始 3）|固定减伤，先减后乘|
|暴击倍率|1.5|暴击率 5%|
|连击加成|1 + min(连击数 × 1.5%, 30%)|20 连封顶 +30%|
|评价修正|S/A/B = 1.00 / 1.00 / 0.95|低评价略降伤害|
|霸体修正|霸体目标受 0.8 倍|霸体是「能扛」不是「减免」|
|最小伤害|1|防 0 伤害|

**算例（难度基准）**

* 普攻 9 点，三连末段 15 点，三连合计 **33 点**。
* 打 40 血近战小怪差 7 点 → 补一刀，或吃一次暴击（11 点）。
* 打 600 血 Boss 约 18 个三连；按 4 秒一个约 **72 秒**，符合「Boss 战 2 分钟」预算。
* 全关总血约 **1210**，纯输出约 100 秒；加移动/演出/重试落在 5–8 分钟。

### 4.5 状态与规则

|规则|定义|
|-|-|
|无敌帧|闪避 1–3 帧、大招 7–12 帧、受击后 0.5s 闪烁|
|霸体|不受硬直与击退，仍受伤害（×0.8）|
|受击硬直|玩家 0.25s / 小怪 0.2s / 盾兵 0.15s / Boss 0.1s|
|击退|招式 40–120px；受击方 60px；撞墙追加 0.2s 硬直；Boss 只退 20px|
|连击|3.0s 内连续命中；每 1 连击 +1.5%，20 封顶；断连清零不惩罚|
|能量|命中 +6、击杀 +15、受击 −10，上限 100|
|空中|二段跳；跳攻 1 次、追击最多 2 段；落地 0.15s 硬直；**空中无闪避**|
|坠落|扣 20 血，回最近安全点，不重置波次|
|同屏攻击者|近战最多 2 只围攻，远程最多 1 只射击|

### 4.6 难度三原则

1. **伤害不致命**：单次受击 5–12 点，100 血可挨 9–20 下，死因通常是位置而非数值。
2. **招式可读**：所有敌人攻击 ≥0.4s 前摇，Boss 红光 + 音效双提示。
3. **失败可归因**：结算页显示「受伤来源」。

|特殊|—|弹道可被闪避穿过|正面减伤 60%，背面 ×1.5，破防 3s|

> 「同屏进攻上限」是最容易被忽略、又最影响体验的一条：没有它，13 只怪一起上就是不可能通关的关卡。

### 7.2 AI 状态

|状态|进入条件|行为|退出|
|-|-|-|-|
|待机|默认|原地呼吸，面向最近玩家|玩家进入索敌距离|
|追击|玩家在索敌内|移动并保持攻击距离|超出 1.5 倍索敌距离|
|攻击|进入攻击距离且冷却就绪|前摇 → 判定 → 收招|招式结束|
|受击|被命中且非霸体|0.2s 硬直 + 击退 + 闪白|硬直结束|
|死亡|HP ≤ 0|死亡动画，掉金币，2s 消失|动画结束|
|**绕圈（等待）**|同屏攻击上限已满|在玩家周围 250px 游走|有名额释放|

### 7.3 Boss「夜巡」（600 血，三阶段）

|阶段|血量|可用招式|行为变化|
|-|-|-|-|
|P1|100%–66%|三连斩、跳劈|间隔 2.0s，直线压制|
|P2|66%–33%|+ 召唤小怪（最多 2 只）|间隔 1.6s，召唤后 1s 硬直|
|P3|33%–0%|+ 狂暴（攻速 ×1.3）|间隔 1.1s，前摇缩短 20%，红光加粗|

|招式|前摇|伤害|范围|预警|可闪避|
|-|-|-|-|-|-|
|三连斩|0.6s|10 ×3|前方 90px，180°|剑身红光闪烁|是|
|跳劈|0.8s|14|落点 140px 半径|地面红圈由外向内收|是（收圈前）|
|召唤|1.0s|0|场地两侧各 1 只|举刀 + 地面裂纹|不可打断，可趁硬直输出|
|狂暴（转阶段）|1.0s|0|全场|怒吼 + 轻震|无敌 1s，不可打断|

转阶段时 Boss 获得 1 秒无敌并清空硬直；召唤的小怪不计入掉落与评价；P3 狂暴不能被打断，但可被「零点」无敌帧硬顶。

> 「公平」不是数值低，而是「看得见、躲得掉」。

## 十一、技术方案

|项|取值|
|-|-|
|引擎|Godot 4.4 stable|
|渲染|Compatibility（2D 足够，兼容老显卡）|
|语言|GDScript|
|分辨率|1920×1080，stretch = canvas\_items，keep 宽高比|
|目标|1080p 60fps，帧预算 16.6ms|
|导出|Windows x86\_64，版本号 `0.2.0.<build>`|

### 11.1 节点结构

|场景|结构|
|-|-|
|Main|Main → GameRoot（切换关卡/UI）|
|Level|Level → TileMap / Spawner / Checkpoints / Camera|
|Player|CharacterBody2D → StateMachine → AnimatedSprite2D → Hitbox(Area2D)|
|Enemy|CharacterBody2D → StateMachine → AnimatedSprite2D → Hitbox / Hurtbox|
|UI|CanvasLayer → HUD / Menus / DamageNumbers|
|AttackHitbox|独立场景，由招式实例化|

### 11.2 碰撞层

`1` 玩家身体 · `2` 敌人身体 · `3` 玩家攻击 · `4` 敌人攻击 · `5` 可破坏物 · `6` 边界/触发器

### 11.3 三条技术约定

1. M1 用手写 enum 状态机，不用 AnimationTree——简单可控。
2. 全部数据走 JSON，**F5 热重载当前关卡**，调数值不重启。
3. 输入缓冲：硬直结束前 0.15s 内按下的指令自动执行；手柄死区 0.25。

### 11.4 性能预算

|项|预算|验收|
|-|-|-|
|总帧时间|16.6ms|压力场景 60 秒|
|逻辑|≤ 4ms|Godot Profiler|
|渲染|≤ 8ms|同上|
|物理|≤ 2ms|同上|
|显存|≤ 512MB|任务管理器|

压力场景：**6 敌人 + 30 特效粒子 + 雨**。

### 11.5 调试工具

* 无敌 / 秒杀 / 跳关 / 显示碰撞盒 / 显示帧数 / 冻结敌人 AI
* 手感调试面板：滑条实时调停顿、震屏、击退
* 控制台：`give\\\_gold`、`set\\\_level`、`spawn boss`、`reload\\\_level`

## 十二、验收标准（M1）

|#|指标|判定|通过线|
|-|-|-|-|
|1|启动到结算|秒表/引擎计时|≤ 8 分钟（目标 5）|
|2|输入响应|录屏逐帧|按键到起手 ≤ 100ms|
|3|三连可接|连续 10 次|成功 ≥ 9 次，无卡帧|
|4|闪避无敌|弹道上闪避 20 次|躲开 ≥ 18 次|
|5|Boss 三阶段|打完整场|三阶段都进入且新增招式生效|
|6|命中反馈四件套|目视+录屏|停顿、震屏、数字、连击同时出现|
|7|死亡与重试|Boss 战故意死|3 秒内可重试，不重打四波|
|8|结算与评价|通关一次|显示 S/A/B、用时、受伤、连击、金币|
|9|存档可靠|强杀进程 5 次|不丢、不损坏、可继续|
|10|性能|压力场景 60 秒|平均 ≥ 58fps，最低 ≥ 50fps|

> 每条都要能「当场演示」。做不到演示的，就不算完成——包括「感觉还行」。

## 十三、里程碑与风险

### 13.1 里程碑（4 周）

|阶段|内容|工期|出口标准|
|-|-|-|-|
|M0|PRD v0.2 + 决策确认|已完成|5 项决策落定|
|M1 灰盒|灰盒关卡、移动/三连/闪避/一个技能、1 种怪、Boss 骨架|1 周|能打通，手感可调|
|M1 成品|全 15 组动作、3 种怪、Boss 三阶段、HUD、结算、存档|2 周|满足验收 1–9|
|M2|手柄、教学、设置、无障碍、性能调优、音效|1 周|满足验收全部|
|M3|第二关、装备商店、多语言（可选）|待定|—|
|M4|联机 / 账号（可选）|不排期|—|

核心思路：把「能玩」和「好看」分开。灰盒周只验证手感，手感不对就调，不浪费动画。

### 13.2 风险与应对

|风险|触发信号|应对|
|-|-|-|
|动作量爆炸|第 1 周动画完成 < 30%|先用色块占位跑通逻辑，美术延后 M2|
|手感调不出来|三连打完「黏」|按 4.2 面板逐项二分：先关震屏，再调停顿，最后调击退|
|范围蔓延|出现「再加角色/关卡」提议|对照非目标表逐条打回|
|美术不一致|新素材与基准色差明显|用 10.2 的五个色值验收，不靠肉眼|
|性能不达标|压力场景 < 50fps|先降特效密度与粒子数，再考虑合批与图集|
|存档损坏|强杀进程后读档失败|原子写入 + `save.bak` 回滚|

风险管理的价值不在列风险，在\*\*「什么时候该启动预案」\*\*。
