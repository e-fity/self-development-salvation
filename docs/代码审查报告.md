### P1-1 存档替换存在「两份都丢」的崩溃窗口，且没有 `save.bak`（✅ 已修复）

**位置**：`game/autoload/save_system.gd:109-132`

```gdscript
if dir.file_exists(SAVE_NAME):
    dir.remove(SAVE_NAME)          # ← 旧档在这一刻已经没了
if dir.rename(TMP_NAME, SAVE_NAME) != OK:
    push_error("[存档] 替换存档失败")
    return false
```

`tmp` 写完后先 `remove(save.json)` 再 `rename`。如果在两步之间进程被杀/断电，磁盘上只剩 `save.tmp`，下次启动 `load_data()` 只找 `save.json` → 直接回落默认值，旧档与新档同时丢失。另外 `flush()` 不是 fsync，掉电时 tmp 内容本身也可能不完整。

PRD 8.4 / 验收第 9 条要求「存档原子写入 + `save.bak` 回滚 + 强杀 5 次不丢档」，当前实现不满足。

**建议**：

```gdscript
const BAK_NAME := "save.bak"

# save_data()
if dir.file_exists(SAVE_NAME):
    if dir.file_exists(BAK_NAME):
        dir.remove(BAK_NAME)
    dir.rename(SAVE_NAME, BAK_NAME)        # 旧档降级为 bak，而不是删除
if dir.rename(TMP_NAME, SAVE_NAME) != OK:
    if dir.file_exists(BAK_NAME):
        dir.rename(BAK_NAME, SAVE_NAME)    # 失败回滚
    return false
return true

# load_data()
# 主档解析失败时再尝试 save.bak；两者都坏才回落默认
```

fsync 需要平台调用（Godot 的 `FileAccess` 没有暴露），至少应在文档里标注「flush 仅保证进程内可见」，并把「强杀不丢档」的验收改为「主档或 bak 至少一份可用」。

### P1-2 `settings` 不是字典时存档加载会类型报错（✅ 已修复）

**位置**：`game/autoload/save_system.gd:80-92`、`:152-160`

```gdscript
for key in data.keys():
    if loaded.has(key):
        data[key] = loaded[key]        # "settings" 可能被覆盖成字符串/数字

var loaded_settings: Dictionary = loaded.get("settings", {})   # ← 类型错误
var merged: Dictionary = data["settings"].duplicate()          # ← 也会炸
```

JSON 是外部可编辑文件，`{"settings": 1}` 是合法 JSON。`load_data()` 号称「文件损坏时绝不崩」，但只校验了顶层是 Dictionary，没有校验嵌套字段类型。`get_setting` / `set_setting`（`:153`、`:158`）同样假定 `settings` 是 Dictionary，坏档进入游戏后第一次读设置就会报错。

**建议**：

```gdscript
var raw_settings: Variant = loaded.get("settings", {})
var loaded_settings: Dictionary = raw_settings if raw_settings is Dictionary else {}
var current: Variant = data.get("settings")
if not (current is Dictionary):
    data["settings"] = default_data()["settings"]
var merged: Dictionary = (data["settings"] as Dictionary).duplicate()
```

`get_setting` 也加同样的类型保护，返回值仍走 fallback。

### P1-3 `Data._merge` 会用标量覆盖字典，导致玩家脚本类型崩溃（✅ 已修复）

**位置**：`game/autoload/game_data.gd:87-95`，调用方 `game/scenes/player/player.gd:144`、`:151`

```gdscript
if base[key] is Dictionary and over[key] is Dictionary:
    base[key] = _merge(base[key], over[key])
else:
    base[key] = over[key]          # move 写成 5 时，整个字典被替换成 5
```

`player.gd` 里：

```gdscript
var mv: Dictionary = d.get("move", {})     # 运行时报「Cannot assign int to Dictionary」
var st: Dictionary = d.get("stats", {})
```

也就是说，`data/player.json` 里手滑把 `"move": {...}` 写成 `"move": 220`（或把 `attacks` 写成对象）时，`Data` 的「静默回落」承诺失效，游戏在玩家 `_ready` 阶段直接报错。`_merge` 对数组元素也不做任何校验。

**建议**：合并时以默认值的类型为准，类型不符就保留默认值并 `push_warning`：

```gdscript
if base[key] is Dictionary:
    if over[key] is Dictionary:
        base[key] = _merge(base[key], over[key])
    else:
        push_warning("[数值] %s 应为对象，已忽略" % key)
    continue
if typeof(over[key]) != typeof(base[key]) \
        and not (base[key] is float and over[key] is int):
    push_warning("[数值] %s 类型不符，已忽略" % key)
    continue
base[key] = over[key]
```

数组（`attacks`）建议单独校验元素必须是 Dictionary 且含 `startup/active/recover/mult/knockback`。

### P1-4 Boss 三连斩的判定高度硬编码，`combo.height` 配置完全不生效（✅ 已修复）

**位置**：`game/scenes/enemies/boss.gd:173`、`:181`、`:194`、`:209`；配置读取在 `:358`、`:369`

```gdscript
# 读入了但没用的两个变量
combo_height = Data.num(c, "height", combo_height)   # boss.json: 160
jump_height  = Data.num(j, "height", jump_height)    # boss.json: 180

# 实际判定盒
Vector2(combo_range, 220.0)        # 三连斩：220 而不是 160
Vector2(jump_range * 2.0, 180.0)   # 跳劈：180，恰好等于配置值
```

三连斩判定盒比配置高 60px：玩家站在 Boss 头顶上方（y 偏移 -160..-220）也会被砍到，而设计意图（`combo.height=160`）是够不到。改 JSON 调手感没有任何效果。

**建议**：两处判定与预警统一改成 `Vector2(combo_range, combo_height)`；跳劈同理用 `jump_height`，避免以后调参再次失效。改完补一条冒烟断言直接读判定尺寸会更好。

**修复（R2）**：`boss.gd` 新增 `_combo_size() / _combo_center() / _jump_size() / _jump_center()` 四个 helper，`_move_combo` 的预警与判定、`_move_jump` 的落点判定全部改走 JSON 的 `combo.height` / `jump.height`；`smoke_test.gd` 断言 `_combo_size() == (120, 160)`、`_jump_size() == (280, 180)`。

### P1-5 关卡计时用墙钟，暂停时间计入成绩（✅ 已修复）

**位置**：`game/scenes/levels/level.gd:17`、`:57`

```gdscript
start_msec = Time.get_ticks_msec()
...
var elapsed := (Time.get_ticks_msec() - start_msec) / 1000.0
```

暂停菜单把 `get_tree().paused` 设为 true 时，`Time.get_ticks_msec()` 继续走。玩家在 Boss 前暂停 30 秒，结算时间和 S 评价都会被拖累；PRD 的「战斗用时」不包含暂停。

**建议**：改为在 `_process(delta)` 里累加（暂停时 `level` 默认 `PROCESS_MODE_INHERIT`，不会执行）：

```gdscript
var elapsed := 0.0
func _process(delta: float) -> void:
    if not _finished:
        elapsed += delta
    _track_checkpoints()
    _track_boss()
```

结算直接读 `elapsed`。这样暂停、设置面板打开（树暂停）都不会计时。

**修复（R2）**：`level.gd` 删除 `start_msec`，改 `var elapsed := 0.0`；`_process(delta)` 先调 `tick(delta)`，`tick()` 在 `_finished` 后停止累加；`_show_results()` 改用 `elapsed`。`smoke_test.gd` 的 Level 组断言 `tick(0.25)×2 == 0.5`，且结算后 `tick(10.0)` 不再增长。

### P1-6 标题页打开设置面板时按 Enter 会直接进入关卡（✅ 已修复）

**位置**：`game/scenes/ui/title.gd:90`、`:136-138`

```gdscript
start.grab_focus()          # 焦点停在「开始游戏」

func _unhandled_input(event):
    if event.is_action_pressed("ui_accept"):
        _on_start()          # 设置面板盖着也照进不误
```

设置面板是 `title` 的子节点，打开后没有接管焦点。此时按 Enter：
- 若焦点仍在被遮住的「开始游戏」上，GUI 会直接触发按钮 → 进关；
- 即使焦点丢失，`_unhandled_input` 兜底也会进关。

玩家想用键盘关设置面板（Esc 可以，但 Enter 是常见确认键）时会瞬间进入战斗。

**建议**：要么删掉 `_unhandled_input` 的兜底（按钮本身已支持键盘聚焦），要么在 `_on_settings` 里记录 `_settings_open = true`，`_unhandled_input` 首行 `if _settings_open: return`，并在面板 `closed` 信号里复位。同时建议设置面板 `_ready` 里 `first_slider.grab_focus()` 或让「返回」按钮拿焦点。

**修复（R2）**：`title.gd` 新增 `_settings_open` 标志与 `_start_btn` 引用：打开面板时禁用「开始 / 继续」按钮、`_unhandled_input` 首行直接 return，面板 `closed` 时复位并恢复焦点；`settings_panel.gd` 的「返回」按钮在 `_build()` 末尾 `grab_focus()`，键盘可直接操作。

### P1-7 Boss 阶段转换期间 `_busy` 仍为 false，可能边无敌边起手（✅ 已修复）

**位置**：`game/scenes/enemies/boss.gd:106-140`、`:305-316`

```gdscript
func _physics_process(delta):
    ...
    if _dead or _busy:
        return
    ...
    _atk_timer -= delta
    if _atk_timer <= 0.0:
        _busy = true
        _choose_attack(player)

func _transition(new_phase):
    phase = new_phase
    _invuln = true
    modulate = Color(1.0, 0.35, 0.35)
    await _wait(transition_seconds)   # 1s 内 _busy 仍是 false
    ...
```

`take_hit` 触发 `_transition` 时不会动 `_busy`。若此时 `_atk_timer` 正好走到 0（或转换 1 秒内走到 0），Boss 会在红色无敌状态下起手，玩家按「红光 = 可闪」的视觉语言会误判，且这段时间 Boss 不吃伤害。

**建议**：`_transition` 开头 `_busy = true`、结束 `_busy = false`（并重置 `_atk_timer`）；或在 `_physics_process` 的 AI 分支加 `if _invuln: return`。同时建议把 `_transition` 期间的 `modulate` 与 `_telegraph` 的红色做区分（例如无敌用暗红、预警用亮红）。

**修复（R2）**：`_transition()` 开头保存 `was_busy` 并置 `_busy = true`，结束时恢复；`_telegraph()` 收尾的白色恢复加了 `not _invuln` 条件，避免转换期暗红被预警提前擦掉。`smoke_test.gd` 断言转换后 `_busy` 为真、1.1s 后 `_invuln` 与 `_busy` 均复位。

### P2-5 受击红闪在闪避/橙闪期间到期会残留红色（✅ 已修复）

**位置**：`game/scenes/player/player.gd:188-193`、`:433-434`、`:467-468`、`:497`

```gdscript
if _hurt_invuln > 0.0:
    ...
    if _hurt_invuln <= 0.0 and state != State.DODGE and state != State.DASH:
        visual.modulate = Color.WHITE      # 闪避/橙闪中不恢复
```

闪避与橙闪每帧只改 `modulate.a`（保留 RGB），而 `modulate` 的 RGB 在受击时被设成 `(1.0, 0.6, 0.6)`。如果 0.5s 受击无敌在闪避/橙闪动作中途结束，红色 RGB 会一直留到 `_end_action()` 的 `Color.WHITE`。表现为「闪完还是红的」半秒。

**建议**：受击闪烁只改 `modulate.a`，把 RGB 交给动作状态；或让闪避/橙闪每帧显式设置完整颜色（`Color(1,1,1,alpha)`），受击红闪用独立叠加层/着色器。

**修复（R3）**：`player.gd` 把 `visual.modulate` 的写入收敛到 `_apply_visual_alpha()`：颜色由 `_flash_tint()`（红闪中 `(1,0.6,0.6)`，否则白）决定，透明度由 `_state_alpha()`（DODGE 0.5 / DASH 0.6）决定；红闪到期时立即用「白 + 当前状态 alpha」刷新，`_end_action()` 也走同一入口。另加 `not _dead` 保护，死亡淡出不再被红闪抢写。`smoke_test.gd` 断言闪避中红闪到期后 `modulate.r == 1.0`、闪避结束 `a == 1.0`。

```gdscript
        label.text = "%d%%" % int(round(stored * 100.0))   # 两个分支完全相同
```

**建议**：删掉 `if/else` 与 `_checks`；若想区分显示，震屏用 `×1.5`、音量用 `75%`。

### P2-7 BGM 循环依赖 `finished` 重播，循环点会有空隙（✅ 已修复）

**修复（R4）**：不改 `.import`（避免重新导入素材），在 `audio.gd` 的 `start_music()` 里给流打开运行时循环：`AudioStreamWAV` 设 `loop_mode = LOOP_FORWARD`、`loop_begin = 0`、`loop_end = 0`（0 表示到样本末尾）；`AudioStreamOggVorbis` 设 `loop = true`。`_music_looped` 记录是否成功，`_on_music_finished()` 只对不支持循环的流兜底重播。`smoke_test.gd` 断言 BGM 载入后 `loop_mode == LOOP_FORWARD`。

### P2-11 自定义存档目录不存在时不会自动创建（✅ 已修复）

**位置**：`game/autoload/save_system.gd:36-44`（`_resolve_paths`）、`:109-118`（写 tmp）

`SALVATION_SAVE_DIR` 指向一个尚未创建的目录时，`FileAccess.open(save.tmp, WRITE)` 返回 `null`，`save_data()` 直接失败；随后 `load_data()` 读不到文件，回落默认值。表现为「存档写了但没保存」。

本次冒烟测试就踩到了这一点：忘记先建目录时，Save 组的 3 条断言（写入存档 / 金币往返 / 通关次数往返）失败，日志为 `[存档] 写不了临时文件`；预先 `New-Item -ItemType Directory` 后当时的 34 条基线全过。

**建议**：`_resolve_paths()` 里补一次目录创建并检查结果：

```gdscript
var made := DirAccess.make_dir_recursive_absolute(_dir)
if made != OK and made != ERR_ALREADY_EXISTS:
    push_error("[存档] 无法创建目录：%s" % _dir)
```

默认 `user://` 目录由引擎创建，所以这条只影响自定义目录与自动化环境，定为 P2；本次冒烟测试已在 `_ready` 里自动创建该目录（见 README 与工程规范 §11.3）。
