# 工程规范

- 版本：v1.0（2026-11-16）
- 适用：本仓库全部内容（`game/` 的 Godot 工程、`tools/` 的脚本、`docs/` 的文档）
- 相关：[README](../README.md)｜[代码规约](代码规约.md)｜[架构与逻辑说明](架构与逻辑说明.md)｜[代码审查报告](代码审查报告.md)｜[PRD](prd/游戏需求文档_v0.2_总结.md)

本规范的目标只有三条：**文件各归其位、数值只有一个来源、改动可验证**。新增内容前先读第 1、6、11 节；提交前过第 12 节的清单。

> 分工：本文件管「文件放哪、流程怎么走」；代码级规则（命名、类型、缩进、JSON 格式、提交信息）见 [代码规约](代码规约.md)，两者配合使用。

```
│  ├─ autoload/              全局单例（Data / Fx / Save / Settings / Audio）

│  ├─ audio/{bgm,sfx}/       音频素材

└─ _backup/                  临时备份（**不提交**，可随时删）
```

归位规则：

| 内容 | 放哪里 | 不要放哪里 |
| --- | --- | --- |
| 游戏脚本、场景、数值、素材 | `game/` 对应子目录 | 仓库根目录 |
| 需求/评审/说明文档 | `docs/`，PRD 进 `docs/prd/` | 根目录、`game/` |
| 文档截图、预览图 | `docs/assets/` | `game/`（会被 Godot 导入成资源） |
| 一次性的生成/处理脚本 | `tools/` 对应子目录 | 根目录 |
| 已跑完不再用的脚本 | `tools/archive/`，文件头加「仅历史留档」 | 根目录 |
| 临时备份、试验输出 | `_backup/`（已在 `.gitignore`） | 仓库任何受版本控制的位置 |

**判定标准**：Godot 会扫描并导入 `game/` 下的所有资源。只要文件不需要在运行时被 `res://` 引用，就不该放进 `game/`。

## 2. 命名规范

| 类别 | 规则 | 示例 |
| --- | --- | --- |
| 目录 | 全小写，复数名词 | `scenes/`, `autoload/`, `tests/` |
| GDScript 文件 | snake_case，与主类语义一致 | `enemy_dummy.gd`、`save_system.gd` |
| 场景文件 | 与主脚本同名，snake_case | `boss.tscn` + `boss.gd` |
| 场景根节点 | PascalCase，与场景名对应 | `Player`、`Boss`、`EnemyDummy` |
| 节点名 | PascalCase，语义化，不用默认名 | `Visual`、`Collision`、`HUD` |
| 变量/函数 | snake_case；私有加 `_` 前缀 | `_atk_timer`、`_do_hit()` |
| 常量 | UPPER_SNAKE_CASE | `CHECKPOINTS`、`SAVE_NAME` |
| 信号 | snake_case，过去式或名词 | `closed`、`boss_defeated` |
| 组（group） | 单数小写 | `player`、`boss`、`level` |
| 输入动作 | snake_case，动词或部位 | `move_left`、`attack`、`dash` |
| JSON 键 | snake_case | `attack_range`、`max_hp` |

禁止：拼音命名、无意义缩写（`tmp2`、`obj`）、同一概念多种叫法（`hp` / `health` / `life` 只能留一个，当前统一为 `hp`）。

## 3. GDScript 代码规范

### 3.1 类型与声明

- 所有成员变量、函数参数、返回值**必须标注类型**；`Variant` 只在确实任意类型时使用并注释原因。
- 节点引用用 `@onready var x: Type = $Path` 或 `@export var x: Type`；禁止裸 `get_node("../../X")` 链式查找。
- 设计师可调的值用 `@export`（如 `attack_power`、`hitbox_size`），代码内固定值用 `const`。
- 容器优先 `Array[Type]` / `Dictionary` 明确用途；不要用 `Array` 存混合类型。

```gdscript
# 推荐
const SAVE_NAME := "save.json"
@export var hitbox_size := Vector2(100, 130)
var _atk_timer: float = 0.0

func take_damage(amount: int, from_dir: float) -> void:
```

### 3.2 缩进与排版

- 缩进按语言：GDScript / `.tscn` 用 **Tab**（宽 4）；JSON 用 **2 空格**；Python 用 **4 空格**（详见[代码规约](代码规约.md) GEN-2）。
- 行尾不留空格；文件末尾留一个空行；GDScript 行宽 ≤ 100（硬上限 120），长表达式换行时运算符置于行首。
- 空行分组：常量 → 导出变量 → 普通变量 → `@onready` → 生命周期函数 → 公开方法 → 私有方法。

### 3.3 注释

- 注释解释**为什么**，不复述代码；复杂公式、帧数换算、平台差异必须写。
- 注释中不得承诺未实现的行为（教训：`audio.gd` 写了「交叉淡化」但素材未做；`game_data.gd` 写了「与 JSON 一致」但已漂移）。
- 临时方案统一写 `# TODO(M2): ...`，并在 PR / 审查报告里登记。

### 3.4 每帧代码红线

`_process` / `_physics_process` 内禁止：

- `new` 形状、查询、Tween、Label 等对象（应缓存成员变量复用）；
- `get_first_node_in_group()` / `find_child()` / `load()` / 字符串拼接路径；
- 遍历整棵场景树；
- 同步磁盘 IO（存档只在结算/设置变更时写）。

例外：目标数量极少且已注释说明的一次性查询（如 `player._do_hit` 每次出手新建 query），可保留但要在审查报告里登记。

### 3.5 字符串路径

场景/脚本引用一律用 `const X := preload("res://...")` 或 `@export_file`，禁止在逻辑里散落 `"res://..."` 字面量（当前 `level.gd` 的 `load("res://scenes/ui/results.gd")` 属待清理项）。

### 3.6 空值与生命周期

- `await` 之后必须重新校验 `is_inside_tree()` / `is_instance_valid()` 再操作节点。
- 节点释放用 `queue_free()`，不要在 `_process` 里 `free()`。
- 场景切换前保存状态；`get_tree().paused` 的恢复责任归设置它的脚本。

## 4. 场景（.tscn）规范

- 场景只负责**结构与静态配置**，动态 UI（HUD、结算、设置）可继续用代码构建，但必须在架构文档登记。
- 根节点命名与场景名一致；根节点脚本只挂一个。
- 碰撞体用 `CollisionShape2D` + 资源内联；不要用代码在 `_ready` 里 `new` 固定碰撞体（美术占位可例外）。
- 需要程序读取的位置（检查点、刷怪点、掉落点）用 `Marker2D` 并在 `_ready` 收集，禁止在脚本里写坐标数组（当前 `CHECKPOINTS = [600, 1600]` 属待改项）。
- `CanvasLayer` 的 `layer` 必须使用下表的值，新增层先更新本表：

| layer | 用途 | 脚本 |
| --- | --- | --- |
| 10 | 战斗 HUD | `hud.gd` |
| 40 | 教学提示 | `tutorial.gd` |
| 50 | 结算页 | `results.gd` |
| 60 | 暂停菜单 | `pause_menu.gd` |
| 80 | 设置面板 | `settings_panel.gd` |
| 100 | 调试面板 | `debug_panel.gd` |

- `process_mode`：UI 与相机在暂停时仍需工作，显式设 `PROCESS_MODE_ALWAYS`；游戏逻辑保持默认继承，靠 `get_tree().paused` 统一暂停。

## 6. 数值与 JSON 规范

### 6.1 文件结构

`game/data/*.json` 顶层必须是对象；允许 `_comment` 键（`Data._merge` 会忽略）：

```json
{
  "_comment": "玩家数值；改完在控制台执行 Data.reload() 热重载",
  "fps": 15,
  "stats": { "max_hp": 100, "attack_power": 12 },
  "attacks": [
    { "startup": 2, "active": 1, "recover": 3, "mult": 1.0, "knockback": 60.0 }
  ]
}
```

格式固定为 **2 空格缩进、双引号、无尾随逗号、文件末尾换行**（与[代码规约](代码规约.md) DATA-1/DATA-2 一致）；三个数据文件已于 2026-11-16 统一，新增文件照此格式。

### 6.2 硬性规则

1. **单一来源**：同一数值只能出现在一处。代码里不得再写一份（当前 `player.gd` 的 `target_defense = 3.0`、`boss.gd` 的 220/180 是反例）。
2. **默认表同步**：`game_data.gd` 的 `DEFAULT_*` 只允许保留「最小可运行」字段；与 JSON 重叠的字段必须同值，并加冒烟断言。
3. **类型一致**：数字用 `Data.num()` 读、布尔用 `Data.flag()` 读；JSON 里禁止把对象写成标量（`_merge` 修好后会保留默认值并告警）。
4. **帧数换算**：动作时序用「帧」表达，代码用 `帧数 / fps` 换算；新增时序字段必须注明单位。
5. **新增字段三件套**：JSON 加键 → `DEFAULT_*` 加同值默认 → `smoke_test.gd` 加一条读取断言。缺一不可。

### 6.3 热重载

`Data.reload()` 可在运行时重读三张表；涉及已生成节点的数值（如 `max_hp`）不会自动回填，改数值后建议重开关卡。调试面板不提供热重载按钮，属已知限制。

## 7. 存档与设置规范

- 存档文件名固定 `save.json`，临时文件 `save.tmp`，目标备份 `save.bak`（**待实现**）。
- 写档流程目标：`写 tmp → flush → 旧档改名 bak → tmp 改名主档 → 失败回滚 bak`。
- `version` 必填且为整数；新增字段走 `_migrate()`，不要改旧字段含义。
- `settings` 必须是对象；读档、`get_setting`、`set_setting` 都要做 `is Dictionary` 保护。
- 测试与多开用环境变量 `SALVATION_SAVE_DIR` 指向独立目录，禁止在测试里写真实 `user://`。
- 存档 schema 变更必须同步更新 [架构与逻辑说明.md](架构与逻辑说明.md) 的存档章节与本文件。

## 8. 输入映射规范

- 动作名 snake_case；不使用 `ui_*` 前缀以外的引擎保留名。
- 新增动作必须同时：`project.godot` 注册 → 代码读取 → README 操作表登记 → 教学文案可用。**四步缺一，不得合入**（当前 `skill2`/`ultimate`/`interact` 只有第一步）。
- 键位表以 README 为准；手柄映射落地前，README 必须标注「仅键鼠」。
- 鼠标攻击需判断 `get_viewport().gui_get_hovered_control() == null`，避免点 UI 触发战斗（`player.gd` 已实现，新增鼠标动作照做）。

## 9. UI 规范

- 全部 UI 用 `Control` 锚点布局，禁止绝对坐标写死（灰盒阶段可例外，但要在代码注释标 `# 灰盒`）。
- 字体统一 `Arial`（`hud.gd` 内的 `_font` 生成方式），新增文本复用同一份字体缓存。
- 按钮：`process_mode = PROCESS_MODE_ALWAYS`，打开面板时手动 `grab_focus()` 到首个可操作项，关闭时把焦点还给入口按钮。
- 面板打开期间必须阻止下层快捷键（标题页 Enter 冲突是反例：面板打开时 `_unhandled_input` 直接进关）。
- 文本中的按键提示必须与实际 InputMap 一致；未实现技能不得出现在教学/标题文案中。

## 10. 素材与音频规范

- 路径：`game/art/<类别>/<名称>.png`、`game/audio/{bgm,sfx}/<名称>.wav`；类别用小写复数。
- 图片：像素图 `filter = nearest`，其余默认；单图 ≤ 2048×2048；`source/` 放原始未处理文件。
- 音频：16-bit / 44.1kHz / 单声道（音效）、立体声（BGM）；BGM 必须开循环（`edit/loop_mode=2`）或改用 Ogg 自带 loop，禁止用 `finished` 重播凑循环。
- 新增素材必须：`.import` 与源文件同目录 → 运行一次 `--import` → 在 README/素材清单登记用途；无引用的素材要么删除，要么在清单标注「未使用」。
- 移动/重命名素材必须同步更新 `.import` 的 `source_file`，或删除 `.import` 后重新导入。

## 11. 测试规范

### 11.1 何时必须加测试

- 修改 `Data` 的合并/兜底逻辑、`Save` 的读写/迁移/战绩规则、`Results` 的评分档位；
- 修改玩家受伤/无敌帧、Boss 阶段转换与无敌；
- 新增 JSON 字段（见 6.2 第 5 条）；
- 修 P1 级缺陷（先加失败用例，再修）。

### 11.2 写法

- 测试放 `game/tests/`，一个测试场景一个脚本，根节点 `Node2D`，`_ready` 内 `await` 逐组执行。
- 断言函数统一 `_ok(cond: bool, msg: String)`，失败打印期望/实际并用 `get_tree().quit(1)` 退出。
- 测试结束前等待必要的计时器（当前 1.1s）再退出，避免 ObjectDB 泄漏误报。
- 测试不得依赖真实存档、真实窗口、网络；用 `SALVATION_SAVE_DIR` 隔离。

### 11.3 运行与基线

```powershell
$godot = "D:\Godot\Godot_v4.7.2-stable_win64_console.exe"
$env:SALVATION_SAVE_DIR = "$PWD\_backup\test-save"
& $godot --headless --path game res://tests/smoke_test.tscn
```

基线：**34 条断言全部通过、退出码 0**。新增断言后同步更新 README 与本文件中的数字。

> 测试脚本会在 `_ready` 里自动创建 `SALVATION_SAVE_DIR` 指向的目录（`save_system.gd` 本身不建目录，见审查报告 P2-11）。因此该变量必须指向可写路径；指向只读目录时 Save 组会失败。

## 15. 变更流程

**加数值**：改 JSON → 改 `DEFAULT_*` 同值 → 加断言 → 跑测试 → 更新架构文档数值表。
**加场景**：放 `scenes/<类别>/` → 根节点 PascalCase → 挂脚本 → 在架构文档节点树表登记 → 必要时加进 `tests/`。
**加 UI 层**：先在第 4 节层号表登记 → 设 `process_mode` → 处理焦点与暂停 → 更新 README 操作说明。
**重构目录**：先备份 → 移动文件 → 全局搜索 `res://` 与脚本内路径常量 → 重导入 → 跑测试与两个场景 → 更新 README/架构文档。
**修 P1**：先在审查报告登记 → 写失败用例 → 修复 → 用例转绿 → 更新报告状态与验证记录。
