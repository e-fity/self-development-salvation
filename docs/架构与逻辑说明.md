# 架构与逻辑说明

本文按「启动 → 玩家 → 敌人 → 关卡 → UI → 数据/存档 → 反馈」的顺序梳理当前灰盒实现（v0.2，Godot 4.7）。
所有路径相对 `game/`；行号对应 2026-11-16 的代码快照。

## 1. 运行拓扑

```
project.godot
  └─ main_scene = res://scenes/ui/title.tscn
        │
        ├─ autoload（引擎先于主场景初始化，顺序有依赖）
        │    Data → Fx → Save → Settings → Audio
        │
        └─ 场景切换
             title.tscn ──「开始游戏」──▶ level.tscn ──Boss 死亡 +1s──▶ results.gd（动态挂载）
                  ▲                          │
                  └────「返回标题」──────────┘
```

`level.tscn` 是唯一可玩关卡，关卡内同时挂 4 个 UI 层（HUD / DebugPanel / PauseMenu / Tutorial）与 Boss、4 只木桩、2 个检查点。

## 2. 启动链路与 autoload 依赖

`project.godot:18-24` 的顺序不是随意的：

| 顺序 | 单例 | 职责 | 依赖 |
| --- | --- | --- | --- |
| 1 | `Data` | 读 `data/*.json`，与内置默认值深合并 | 无 |
| 2 | `Fx` | 命中停顿、震屏、伤害数字 | `Audio`（延迟调用，运行时才用到） |
| 3 | `Save` | 存档读写、设置项、战绩 | 无 |
| 4 | `Settings` | 建 BGM/SFX 总线并把存档设置应用到运行时 | `Save`、`Fx` |
| 5 | `Audio` | 音效池、BGM、按钮点击音 | `Settings`（总线必须先存在） |

`Audio._ready()` 在 `AudioServer` 里找不到 `SFX` 总线时会退回 `Master`（`autoload/audio.gd:19-21`），所以即使 `Settings` 被禁用也不会静音崩溃，但音量滑条会失效。

## 3. 场景与节点树

| 场景 | 根节点 | 子节点（关键） | 脚本 |
| --- | --- | --- | --- |

`project.godot:90-97` 声明 6 层，但当前只用到 3 层：

## 4. 玩家状态机

`player.gd:43` 定义 `enum State { IDLE, ATTACK, DODGE, DASH, DEAD }`，`_physics_process` 按状态分派（`player.gd:201-211`）。没有 AnimationTree / 独立 StateMachine 节点，符合 PRD M1「手写 enum 状态机」。

```
                 ┌──────────── 输入（优先级：闪避 > 橙闪 > 普攻）────────────┐
                 ▼                                                          │
  IDLE ──attack(地面)──▶ ATTACK ──active 窗口──▶ _do_hit ──收招/缓冲──┐      │
   │  └─attack(空中)──▶ ATTACK(跳攻, 最多 2 段)                        │      │
   │                                                                  ▼      │
   ├─dodge(地面,CD=0)──▶ DODGE ──5 帧/160px──▶ IDLE                          │
   ├─skill1(CD=0)─────▶ DASH ──8 帧/220px──▶ IDLE                            │
   └─take_damage 且 HP≤0──▶ DEAD ──1.5s──▶（回检查点）──▶ IDLE               │
                                                                              │
  ATTACK 收招阶段 + dodge 按下 ──▶ DODGE（取消硬直）──────────────────────────┘
```

### 移动与跳跃（`player.gd:273-325`）

- 水平：`velocity.x = 输入 * 220 + _knock`，击退 `_knock` 以 900 px/s² 衰减（`:303-304`）。
- 重力 1400；地面重置 `_jumps_left = max_jumps`。
- 二段跳：空中 `jump` 且 `_jumps_left > 0` 时 `velocity.y = jump_velocity * 0.8`。
- 空中攻击落地后进入 0.15s 落地硬直（`_air_attacks > 0` 时设置 `_land_lock`，`:288-290`）。
- 输入优先级写死在 `:314-323`：闪避 > 橙闪 > 普攻。

### 攻击帧数据（`player.gd:357-412`）

JSON 里的 `startup/active/recover` 是**帧**，运行时除以 `fps`（默认 15）换算成秒：

| 招式 | startup | active | recover | 总时长 | 倍率 | 击退 |
| --- | --- | --- | --- | --- | --- | --- |
| 普攻 1/2 | 2 帧 0.133s | 1 帧 0.067s | 3 帧 0.2s | 0.4s | ×1.0 | 60 |
| 普攻 3 | 3 帧 0.2s | 2 帧 0.133s | 3 帧 0.2s | 0.533s | ×1.5 | 160 |
| 跳攻 | 2 | 2 | 3 | 0.467s | ×1.0 | 40 |
| 橙闪 | — | 无敌帧 3..5 | 8 帧 0.533s | — | ×1.5 | 120 |

- `_begin_attack` 只算时间窗，真正的命中在 `_state_time ∈ [startup, startup+active)` 内触发一次（`_hit_done` 去重）。
- 地面三连靠 `_buffered`：攻击中再按一次攻击会缓存，收招后自动接下一段；否则结束后 `_combo_next` + `combo_grace` 0.45s 内仍可接续（`:399-410`）。
- 空中攻击不吃缓冲，必须「一按一段」，最多 2 段（`max_uses`）。

### 闪避 / 橙闪（`player.gd:416-487`）

两者都不是「按时间给速度」，而是**按剩余距离推进**，保证总位移精确：

```
speed = distance / (frames / fps)
step  = min(speed * delta, remaining)
velocity.x = dir * step / delta
```

- 闪避：地面限定，5 帧走完 160px，帧 1..3 无敌（`frame >= invuln_from-1`），CD 1.2s。
- 橙闪：空中也能起手，8 帧共 220px，前 5 帧位移，帧 3..5 无敌且触发一次判定，CD 6s；`_process_dash` 不加重力，所以空中橙闪会短暂悬停。
- 无敌由 `invulnerable` 布尔表示，`take_damage` 在 `:221` 直接拒绝。

### 受击、死亡与重生（`player.gd:220-271`）

1. `take_damage(amount, from_dir)` 检查 `_dead / invulnerable / _hurt_invuln`；
2. 扣血、`hits_taken += 1`、`_hurt_invuln = 0.5`（0.5s 受击无敌 + 红闪）；
3. 视觉统一走 `_apply_visual_alpha()`：`_flash_tint()` 决定 RGB（红闪中 `(1,0.6,0.6)`，否则白），`_state_alpha()` 决定透明度（闪避 0.5 / 橙闪 0.6 / 其他 1.0）；红闪到期时立即按「当前状态」刷新，不会把红色带进动作结束；
4. `_knock = from_dir * 240`（不直接写 `velocity.x`，因为 `_process_move` 每帧覆盖）；
5. `Fx.impact(amount, false)` + 受伤音 + 伤害数字；
6. 若在 `ATTACK` 中则 `_end_action()` 打断；
7. HP ≤ 0 → `_die()`：`state = DEAD`、1.5s 后 `_respawn()` 到 `level.respawn_point`，满血 + 1s 无敌。

### 命中判定（`player.gd:500-535`）

```gdscript
query.shape = _hit_shape          # 100×130（@export，场景里可改）
query.transform = Transform2D(0, global_position + Vector2(offset.x * _facing, offset.y))
query.collision_mask = 2          # enemy 层
query.exclude = [get_rid()]
hits = space.intersect_shape(query, 8)
```

- 伤害公式：`max(1.0, attack_power * mult - defense)`，`attack_power=12`、木桩 `defense=3` → 一段 9、三段 15、橙闪 15。
- 同一次动作对同一目标只结算一次（`_hit_ids` 存 instance_id）。
- 每次命中：`combo += 1`、`max_combo` 取大、`_combo_timer = 3s`；多目标时用最大伤害触发一次 `Fx.impact`。
- 注意 `target_defense` 在 `:521-523` 有硬编码兜底 `3.0`，与 `data/enemies.json` 的 defense 重复。

## 5. 木桩 AI（`scenes/enemies/enemy_dummy.gd`）

状态由几个布尔量隐式表达，没有 enum：

| 阶段 | 条件 | 行为 |
| --- | --- | --- |
| 待机/追击 | `distance > attack_range` 且 `< sight(420)` | 以 `move_speed` 走向玩家，按 dx 翻面 |
| 前摇 | 进入攻击距离 | 变红 + 前压，`windup` 0.45s |
| 出手 | 前摇结束且仍在判定盒内 | 前冲、白弧 tween、`swing_heavy` 音、`player.take_damage(damage=8)` |
| 冷却 | 出手后 | `cooldown` 1.6s 内不再出手 |
| 浮空 | `take_hit` 的 `force >= launch_threshold(120)` | `velocity.y = launch_velocity(-430)`，改用 `juggle_gravity(900)`，落地解除且不进攻 |

受击：`hp -= dmg`（伤害已由玩家侧减过防御）、`_knockback = dir * force`（1800/s 衰减）、闪白 `flash_time`；HP ≤ 0 → 禁用碰撞、`parent.add_gold(gold)`（有 `has_method` 保护）、0.25s 淡出 `queue_free`。

`_hits_player()`（`enemy_dummy.gd:169-190`）用**预建并复用**的 `_hit_shape` / `_hit_query` 做 `intersect_shape`，只更新 `size`（配置变了才改）与 `transform`，不再每物理帧分配对象。

## 6. Boss「夜巡」AI（`scenes/enemies/boss.gd`）

### 阶段与节奏

| 阶段 | 触发 | 攻击间隔 | 前摇倍率 | 新增招式 |
| --- | --- | --- | --- | --- |
| P1 | 初始 600 HP | 2.0s | ×1.0 | 三连斩、跳劈 |
| P2 | HP ≤ 66% | 1.6s | ×1.0 | + 召唤（45% 概率，场上无存活召唤时） |
| P3 | HP ≤ 33% | 1.1s | ×0.8 | 同上，节奏更快 |

阶段切换 `_transition`（`boss.gd:319-333`）：先保存并置 `_busy = true`（转换期锁招），`phase = new`、`_invuln = true`、变红，1s 后恢复白色与无敌、还原 `_busy`，并把 `_atk_timer` 压到 ≤0.8s。

### 主循环（`boss.gd:106-140`）

1. 重力 + 非跳跃时 `velocity.x = 0`；
2. 玩家进入 `engage_range(520)` 才 `active = true` 并播 `boss_roar`；
3. `_busy` 为 false 时每帧朝玩家翻面，`_atk_timer` 递减到 0 → `_busy = true` → `_choose_attack`；
4. 招式结束后 `_busy = false`，`_atk_timer = phase_interval[phase-1]`。

### 招式选择（`:150-166`）

```
若 phase ≥ 2 且场上无召唤 且 randf() < 0.45 → 召唤
否则若 |dx| > 260 → 跳劈
否则 → 三连斩
```

| 招式 | 预警 | 判定 | 伤害 |
| --- | --- | --- | --- |
| 三连斩 | `0.6s × windup`，身前矩形 `(combo.range, combo.height)`，中心 `(facing*range/2, -height/2)` | 每 0.28s 判一次，共 3 次 | 10/次 |
| 跳劈 | `0.5s × windup`，先按玩家当前位置画预警框 `(jump.range*2, jump.height)` | 朝玩家方向 `velocity=(±620, -700)` 飞 0.45s，落点矩形同尺寸，中心 `(0, -height/2)` | 14 |
| 召唤 | `1.0s × windup`，无矩形预警 | 在 `x ± 280` 生成 2 只 `enemy_dummy.tscn` | — |

判定尺寸由 `_combo_size()/_combo_center()/_jump_size()/_jump_center()` 统一计算，直接读 `combo.height` / `jump.height`（默认 120×160 与 280×180），改 JSON 即生效。

### 受击与死亡

- `take_hit` 在 `_dead` 或 `_invuln` 时直接 return；扣血后按 `hp/max_hp` 与阈值决定是否 `_transition`。
- `_die`：禁用碰撞、`remove_from_group("boss")`、`add_gold(50)`、0.6s 淡出。
- 关卡侧靠「组里没有 boss」判定胜利（`level.gd:40-47`），HUD 靠同样的信号关血条并显示 3s VICTORY（`ui/hud.gd:106-126`）。

## 7. 关卡流程（`scenes/levels/level.gd`）

```
_ready              → add_to_group("level")、Audio.start_music()
_process 每帧        → tick(delta) + _track_checkpoints() + _track_boss()
  checkpoint x≥600  → respawn_point=(600,0)
  checkpoint x≥1600 → respawn_point=(1600,0) 且 player.hp = max_hp（神龛）
  boss 在组里        → _boss_seen = true
  boss 消失且曾见过   → 1s 后 _show_results()
_show_results       → 隐藏 HUD/DebugPanel → 动态 new results.gd → setup(stats) → paused=true
```

- 金币：木桩 8、Boss 50，`add_gold()` 只改内存并播音效；通关时由 `results.setup` 调 `Save.record_run` 一次性落盘。
- 用时：`tick(delta)` 里 `elapsed += delta`，只累计帧时间；暂停/设置面板（树暂停）不跑 `_process`，所以不计入；`_finished` 之后停止累计。
- 关卡地面宽 3600（x 约 -600..3000），左右没有边界墙；玩家可以走出左端掉落，但 `_die` 后仍会回检查点。

### 结算评分（`ui/results.gd:112-135`）

分三段档位相加，不是线性公式：

| 维度 | 满分条件 | 中档 | 低档 |
| --- | --- | --- | --- |
| 时间（40） | ≤150s → 40 | ≤240s → 24 | 其余 → 10 |
| 受伤（35） | 0 次 → 35 | ≤3 次 → 24 | 其余 → 10 |
| 连击（25） | ≥30 → 25 | ≥15 → 17 | 其余 → 8 |

合计 ≥90 → S，≥70 → A，否则 B。

### 标题页流转

- 标题页打开设置面板时 `_settings_open = true`，禁用「开始 / 继续」并让 `_unhandled_input` 早退；面板关闭（`closed`）后复位并恢复焦点到「开始」。
- 「继续」只在 `clears > 0` 时可用，文本显示最好评价/金币/通关次数；点击行为与「开始」相同（没有真正的存档进度续关）。
- 设置面板是运行时 `preload(...).new()` 挂到标题 Control 下，关闭时自 `queue_free()`；面板内「返回」按钮在 `_build()` 末尾拿焦点，键盘可直接操作。

## 9. 数值系统

`autoload/game_data.gd`：

```
reload() → 对 player/enemies/boss 分别 _load(path, DEFAULT_*)
_load()   → 文件缺失/打不开/JSON 坏 → duplicate(DEFAULT) 返回
         → 成功则 _merge(base, json)
_merge()  → 只遍历 base 已知键；两边同类型才递归/覆盖，标量盖字典会被拒并告警
num()/flag() → 取标量时校验类型，不对就回落
```

设计意图是「删掉 data 目录也能跑」。`_merge` 对类型不匹配的字段会 `push_warning` 并保留默认值（例如把 `move` 写成数字），调用方拿到的始终是与默认表同构的数据；数组还要求长度一致、元素逐个深合并。`DEFAULT_*` 与 JSON 的重叠字段由冒烟测试断言同值（规约 DATA-6）。

## 10. 存档（`autoload/save_system.gd`）

```
_save_path = user://save.json   （SALVATION_SAVE_DIR 可覆盖目录，目录不存在会自动建）
_bak_path  = user://save.bak
default_data():
  {version:1, gold:0, best_grade:"", best_time:0.0, clears:0,
   settings:{bgm:1.0, sfx:1.0, shake:1.0, numbers:true, tutorial:true}}

load_data()  → 默认值起步 → 读主档 → 主档缺失/损坏则读 save.bak → 逐键类型校验 → settings 补键 → _migrate
save_data()  → 建目录 → 写 save.tmp + flush + close → 旧档改名 save.bak（覆盖旧 bak）→ tmp 改名主档
record_run() → gold 累加、clears+1、best_grade 取高、best_time 取小 → save_data()
```

写入顺序保证任意时刻至少有一份可用存档：崩溃在「旧档改名 bak」之前，主档完好；崩溃在「tmp 改名主档」之前，主档缺失但 bak 可读，`load_data()` 会自动恢复。`fsync` 未实现（Godot `FileAccess` 不暴露），只能保证 `flush()` 后进程内可见，掉电场景依赖「主档或 bak 至少一份可用」。

设置项通过 `Settings.apply()` 应用：BGM/SFX 总线音量（`linear_to_db`，≤0.001 静音）、`Fx.shake_scale`、`Fx.numbers_enabled`；`tutorial` 由教学层每帧查询。

## 11. 反馈层

| 系统 | 入口 | 实现 |
| --- | --- | --- |
| 命中停顿 | `Fx.impact(dmg)` | 按伤害分档 40/55/80ms，`Engine.time_scale = 0` + 真实时间计时器（`create_timer(..., ignore_time_scale=true)`）；token 保证重叠时以最后一次为准 |
| 震屏 | 同上 | 2/4/6px × 设置倍率 × 调试倍率，`Camera2D.shake()` 用真实时间衰减 offset |
| 伤害数字 | `Fx.damage_number(pos, dmg)` | 在 `current_scene` 上建 Label（z=100），上飘 46px/0.45s 后 `queue_free`；tween 忽略 time_scale |
| 命中音 | `Audio.play_hit(dmg)` | 与停顿/震屏同一套分档：`hit_light/mid/heavy` |
| 连击 | `player._do_hit` | 每次命中 +1，3s 无命中清零；HUD 只显示 ≥2 |

命中停顿期间 `Engine.time_scale = 0`，物理与 `_process` 的 delta 都变 0，但摄像机震屏与 tween 用真实时间继续，所以「停顿+抖动」能同时发生。

## 12. 关键不变量（测试覆盖点）

1. `Data.num/flag` 对错误类型永远返回 fallback。
2. 缺文件时 `Data` 回到内置默认值，游戏可启动；`_merge` 拒绝标量覆盖字典，默认表与 JSON 重叠字段同值。
3. 存档写→读→再写后金币/次数/评价/最快用时符合 `record_run` 规则；主档损坏时从 `save.bak` 恢复，两者都坏才回落默认值。
4. 玩家受伤扣血、0.5s 内二次伤害被忽略、无敌结束后可再次受伤。
5. 木桩 `hp -= dmg`，血量归零 `_dead = true`。
6. Boss HP 600、阶段阈值 66%/33%、转换期 `_invuln` 拒绝伤害且 `_busy` 锁招；判定盒尺寸取自 `combo.height` / `jump.height`。
7. 结算档位：完美 S、中局 A、差局 B。
8. 关卡计时按帧 delta 累计，结算后停止增长。

以上 8 组共 65 条断言已落在 `tests/smoke_test.gd`，headless 运行退出码 0。

## 13. 与 PRD 目标架构的差异

| PRD 目标 | 当前实现 | 影响 |
| --- | --- | --- |
| Player → StateMachine 子节点 + AnimatedSprite2D | 单脚本 enum 状态机 + Polygon2D/单张 Sprite2D | 功能可用，动画/扩展性未落地 |
| AttackHitbox 独立场景（Area2D，层 3/4） | `intersect_shape` 直接查询，层 3/4 空置 | 无编辑器可视化，但少一层节点开销 |
| 手柄死区 0.25 | 只有键鼠映射，deadzone 0.2 | 未实现手柄 |
| 文案集中 `strings.csv` | 中文硬编码在脚本 | 本地化成本高 |
| 存档 `tmp → fsync → rename` + `save.bak` | `tmp → 旧档改名 bak → rename`，有 bak 无 fsync | 已满足「至少一份可用」，掉电语义略弱于 PRD |
| 导出 `export_presets.cfg` 0.2.0.build | 无导出配置 | 无法一键出包 |
| 数值 F5 热重载 | 手动 `Data.reload()` | 可用，但非自动 |
| 音频总线 Music/SFX/Ambient/Voice + −16 LUFS | 运行时建 BGM/SFX 两条，无总线布局资源 | 够用，缺 Ambient/Voice |

这些差异在 `代码审查报告.md` 中按「未落地」而非「缺陷」归类。
