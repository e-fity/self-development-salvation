# 代码规约

- 版本：v1.0（2026-11-16）
- 效力：本规约管「代码怎么写」，[工程规范](工程规范.md)管「文件放哪、流程怎么走」。二者重叠处以本规约为准（更具体）；目录、流程、职责以工程规范为准。
- 原则：**不重新发明规范**。凡是成熟标准已覆盖的，直接引用并落地；本规约只补充项目特有约束。

## 1. 效力与用词

采用 [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119) 的三级用词：

| 用词 | 含义 | 违反后果 |
| --- | --- | --- |
| **必须**（MUST） | 无条件遵守 | 阻断合入 |
| **应当**（SHOULD） | 默认遵守，偏离需说明理由 | 评审需给出理由 |
| **可以**（MAY） | 可选建议 | 不阻断 |

规则编号用于评审与豁免登记（如 `GD-8`），不要在评审意见里只写「不符合规范」。

## 3. 通用规约（GEN）

| ID | 级别 | 规则 |
| --- | --- | --- |
| GEN-1 | 必须 | 源文件 UTF-8（无 BOM）、LF 行尾、文件末尾一个换行、行尾无空白 |
| GEN-2 | 必须 | 缩进按语言：GDScript / `.tscn` 用 Tab（宽 4）；JSON 用 2 空格；Python 用 4 空格；Markdown 不限制 |
| GEN-3 | 必须 | 行宽：GDScript 必须 < 100 字符（官方硬性建议，尽量 80）；Python ≤ 88；Markdown ≤ 120（表格与链接除外） |
| GEN-4 | 必须 | 标识符一律英文；禁止拼音（`cheng`、`shan`）与无意义缩写（`tmp2`、`obj`）；同一概念只用一个词（统一 `hp`，不混用 `health`/`life`） |
| GEN-5 | 应当 | 一个文件一个主要职责；单文件 > 600 行或单函数 > 80 行时评审是否拆分 |
| GEN-6 | 必须 | 禁止魔法数：可调数值进 `game/data/*.json`；工程常量提为 `const` 并注释来源（帧率、池大小等） |
| GEN-7 | 必须 | 注释解释**为什么**，不复述代码；临时方案写 `TODO(M阶段/负责人): 内容` 并在审查报告登记 |
| GEN-8 | 必须 | 禁止死代码、注释掉的旧实现、常驻 `print`；运行期提示用 `push_warning` / `push_error` |
| GEN-9 | 应当 | 可预期失败返回 `null` / `false` 并 `push_warning`；不可恢复错误 `push_error`，但不得让主流程崩溃 |
| GEN-10 | 必须 | 行为变更必须同时更新测试与文档；只改代码不改文档的提交视为未完成 |

## 4. GDScript 规约（GD）

对齐 Godot 官方 style guide，补充项目约束。

| ID | 级别 | 规则 |
| --- | --- | --- |
| GD-1 | 必须 | 文件 `snake_case.gd`；`class_name`、节点、枚举名 PascalCase；函数/变量/信号 snake_case；常量与枚举成员 CONSTANT_CASE；私有成员与内部函数加 `_` 前缀；信号用过去式（`door_opened`、`score_changed`） |
| GD-2 | 必须 | 成员变量、函数参数、返回值标注类型；类型写在赋值同一行时优先 `:=`，类型不明确时显式标注；`Variant` 仅在确实任意类型时使用并注释原因 |
| GD-3 | 必须 | 文件内顺序（对齐官方）：`@tool` → `class_name` → `extends` → `##` 文档注释 → 信号 → 枚举 → 常量 → `@export` → 公开变量 → 私有变量 → `@onready` → 生命周期（`_init`/`_ready`/`_process`…）→ 公开方法 → 私有方法 → 内部类 |
| GD-4 | 应当 | 函数与类定义之间空 2 行，函数内逻辑段空 1 行；多行数组/字典/枚举在最后一项后加尾随逗号（单行不加） |
| GD-5 | 必须 | 节点引用用 `@onready var x: T = $Path` 或 `%UniqueName`；禁止在 `_process` / `_physics_process` 里 `get_node` / `find_child` / 字符串拼路径 |
| GD-6 | 必须 | 信号在 `_ready` 里用 `Callable` 连接；跨场景通信优先信号或组，不直接抓对方私有变量 |
| GD-7 | 必须 | `await` 之后必须重新校验 `is_instance_valid()` / `is_inside_tree()`；节点释放用 `queue_free()`，不在帧内 `free()` |
| GD-8 | 必须 | 每帧代码红线：不 `new` 形状/查询/Tween/Label，不 `load()`，不读写磁盘，不遍历场景树，不做字符串拼接路径；需要的对象在 `_ready` 建好复用 |
| GD-9 | 必须 | 数值读取统一走 `Data.num()` / `Data.flag()` 并给缺省值；帧数到秒的换算集中一处（`/ fps`），新增时序字段注明单位 |
| GD-10 | 必须 | 禁止常驻 `print`；调试信息进 `debug_panel`，异常路径用 `push_warning` / `push_error` |
| GD-11 | 应当 | 工程设置里把 `UNTYPED_DECLARATION`、`INFERRED_DECLARATION`、`UNSAFE_*` 系列设为警告，保持 0 新增警告 |
| GD-12 | 应当 | 提交前用编辑器格式化或 `gdformat`；接入 gdtoolkit 后 `gdlint` 必须通过 |
| GD-13 | 应当 | 注释 `#` / `##` 后加一个空格（注释掉的代码除外）；对外 API 写 `##` 文档注释；普通实现用 `#`，中文即可 |
| GD-14 | 应当 | 布尔运算符用 `and` / `or` / `not`，不用 `&&` / `\|\|` / `!`；一行只写一条语句（三元表达式除外）；不加多余括号 |

反例（当前代码里已存在，修复前不新增同类写法）：

```gdscript
# 反例：每帧分配 + 每帧查组
func _physics_process(_dt: float) -> void:
    var shape := RectangleShape2D.new()
    var q := PhysicsShapeQueryParameters2D.new()
    var p := get_tree().get_first_node_in_group("player")

# 正例：成员复用 + 缓存引用
var _shape := RectangleShape2D.new()
var _query := PhysicsShapeQueryParameters2D.new()
@onready var _player: Node2D = get_tree().get_first_node_in_group("player")
```

## 5. Python 工具规约（PY）

`tools/` 下的脚本是工程工具，不是产品代码，但同样要求可重复、可维护。

| ID | 级别 | 规则 |
| --- | --- | --- |
| PY-1 | 必须 | 遵循 PEP 8：4 空格缩进、snake_case、UPPER 常量、双引号字符串（Black 默认风格） |
| PY-2 | 必须 | 模块顶部 docstring 说明用途、依赖、用法（PEP 257）；公共函数写一行摘要 |
| PY-3 | 应当 | 公共函数与返回值加类型注解（PEP 484/585，如 `list[str]`） |
| PY-4 | 必须 | 路径用 `Path(__file__).resolve().parents[2]` 定位仓库根；禁止盘符绝对路径、`C:\Users\...`、当前工作目录假设 |
| PY-5 | 必须 | 入口写 `main()` + `if __name__ == "__main__":`；参数用 `argparse`，带 `--help` 与默认值 |
| PY-6 | 必须 | 第三方依赖写进 docstring（含安装命令）；缺依赖时输出可读错误而不是 Traceback |
| PY-7 | 必须 | 脚本可重复运行；覆盖或删除已有文件前必须备份或要求 `--force` |
| PY-8 | 应当 | 用 Ruff（`E,F,W,I,UP,B`）与 Black（88）检查；未接入前至少 `python -m py_compile` 全过 |
| PY-9 | 必须 | 不写入密钥、账号、个人目录；不联网上传仓库内容 |

推荐配置（接入时放仓库根 `pyproject.toml`）：

```toml
[tool.black]
line-length = 88

[tool.ruff]
line-length = 88
select = ["E", "F", "W", "I", "UP", "B"]
```

## 6. 数值 JSON 规约（DATA）

`game/data/*.json` 是策划可直接编辑的数据文件，格式稳定性优先。

| ID | 级别 | 规则 |
| --- | --- | --- |
| DATA-1 | 必须 | 顶层是对象；键 snake_case；字符串双引号；UTF-8 无 BOM |
| DATA-2 | 必须 | 2 空格缩进、冒号后 1 个空格、无尾随逗号、文件末尾换行 |
| DATA-3 | 必须 | JSON 不支持注释；说明写 `_comment` 单行字符串（`Data._merge` 忽略未知键） |
| DATA-4 | 必须 | 数字用十进制，不用科学计数法/千分位；布尔用 `true`/`false`；避免 `null` |
| DATA-5 | 应当 | 单位进键名或 `_comment`（`_px`、`_ms`、`_deg`），避免「这个 160 是像素还是帧」 |
| DATA-6 | 必须 | 与 `DEFAULT_*` 默认表重叠的字段必须同值；新增字段走「JSON → 默认表 → 冒烟断言」三件套 |
| DATA-7 | 必须 | 数组元素结构一致（同为对象、同键），禁止数字与对象混排 |

## 7. 场景与资源规约（SC）

| ID | 级别 | 规则 |
| --- | --- | --- |
| SC-1 | 必须 | 场景与主脚本同名同目录（`boss.tscn` ↔ `boss.gd`）；根节点 PascalCase |
| SC-2 | 必须 | 资源路径全小写 snake_case；引用用 `res://` 绝对路径，不写相对路径 |
| SC-3 | 必须 | `.uid` 与 `.import` 随源文件提交；`.godot/` 不提交（见 `.gitignore`） |
| SC-4 | 必须 | 场景只放静态结构与配置；用代码构建的 UI 必须在工程规范 §4 的层号表登记 |
| SC-5 | 应当 | 需要程序读取的位置（检查点、刷怪点）用 `Marker2D` 或导出数组，不写死坐标 |
| SC-6 | 必须 | 新增碰撞层先在工程规范 §5 的层表登记；不用 `layer=0` 的隐形墙凑数 |

## 8. 提交与版本规约（GIT）

| ID | 级别 | 规则 |
| --- | --- | --- |
| GIT-1 | 必须 | 提交信息遵循 Conventional Commits：`<type>(<scope>): <摘要>`，type 限 `feat`/`fix`/`refactor`/`docs`/`test`/`chore`/`asset` |
| GIT-2 | 必须 | 一次提交一件事；纯格式化与行为修改分开提交 |
| GIT-3 | 必须 | 版本遵循 SemVer；对外构建号 `<主>.<次>.<补丁>.<build>`（PRD 要求 0.2.0.\<build\>） |
| GIT-4 | 应当 | 维护 `CHANGELOG.md`（Keep a Changelog 结构：Added / Changed / Fixed / Removed） |
| GIT-5 | 必须 | 不提交 `.godot/`、`_backup/`、`__pycache__/`、`save.json`、`*.tmp`、`build/` |
| GIT-6 | 应当 | 首行 ≤ 72 字符；正文写「为什么改」，不写「改了哪几行」（diff 已有） |

示例：

```
fix(save): 写档改为先备份再替换，避免崩溃丢档

remove→rename 之间崩溃会同时丢主档与临时档。改为旧档降级 save.bak，
rename 失败时回滚；解析失败时回退 bak。
```

## 9. 文档规约（DOC）

| ID | 级别 | 规则 |
| --- | --- | --- |
| DOC-1 | 必须 | Markdown 使用 ATX 标题（`#`），层级不跳级；代码块标语言；表格前后留空行 |
| DOC-2 | 必须 | 链接用相对路径；路径含空格/中文时用 `<>` 包裹 |
| DOC-3 | 应当 | 术语统一：Boss、木桩（enemy_dummy）、橙闪（skill1/dash）、结算、检查点；不混用同义词 |
| DOC-4 | 应当 | 结论尽量带 `文件:行号`；命令写成可直接复制执行的代码块 |
| DOC-5 | 必须 | 文档与代码同提交；PRD 只增版本不改历史文件 |

## 10. 执行方式

### 10.1 提交前最小检查集

```powershell
# 1) 一键静态检查（Python 语法 / JSON / 文本卫生 / GDScript 基础）
python tools/check.py

# 2) 静态检查 + Godot 冒烟（150 条基线 + 两个场景各跑 120/300 帧）
python tools/check.py --godot
```

`tools/check.py` 对应本文件 §10.2 中标「已接入」的条目；Godot 可执行文件按 `--godot-bin` → `GODOT_BIN` → `PATH` 的顺序查找，都找不到时只跑静态检查。仓库已带 `.githooks/pre-commit`，启用方式：

```powershell
git config core.hooksPath .githooks
```

钩子只跑 `--fast`（不启动 Godot），确保每次提交至少通过静态检查。

| 规约 | 自动检查 | 现状 |

## 11. 豁免与修订

**豁免登记格式**（写在 PR 描述或 [代码审查报告](代码审查报告.md) 尾部）：

```
豁免：GD-8
位置：game/scenes/enemies/enemy_dummy.gd:173
原因：灰盒阶段每帧查询，目标数 ≤ 4；接堆怪系统前必须改为复用
期限：M2 前
```

**已登记例外**：

| ID | 内容 | 理由 | 期限 |
| --- | --- | --- | --- |
| E-1 | JSON 键用 snake_case（Google JSON Style Guide 建议 camelCase） | 与 GDScript 字段读取、`Data` 默认表保持一致，避免映射层 | 长期 |

**修订**：新增/修改规则需在提交信息里写明规则 ID 与理由；删除规则需说明替代标准。
